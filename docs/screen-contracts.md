# Wolfari Web — Screen Contracts

Tài liệu này là hợp đồng giữa thiết kế Figma, UI code, fixture và Gateway adapter. Không implement một flow mới nếu thiếu các mục bắt buộc bên dưới.

## Contracts: Create Trip, Dress Code, Packing List và Trip Map (18/10/2026)

| Screen | Route | Read/write contract | Trạng thái và giới hạn |
| --- | --- | --- | --- |
| Create Trip | `/trips/new` | Draft `v1` gồm name, description, start/end date và timezone `Asia/Ho_Chi_Minh`; chỉ lưu `sessionStorage` trong tab | Validation name 1–200, ngày bắt buộc và end ≥ start. Date-only → RFC3339 chưa chốt nên submit giữ draft, hiển thị unavailable và không gọi repository. `CreateTripSuccess` chỉ nhận `tripId` từ kết quả `created`. |
| Dress Code | `/trips/:tripId/dress-code` | Đọc `PlanViewModel.dressCodes` qua `useTripPlanSnapshot` | Nhóm TRIP/DAY/ACTIVITY; activity mất liên kết có fallback. Không ảnh, palette, live AI hoặc write control. DSS là source lịch sử. |
| Packing List | `/trips/:tripId/packing` | Đọc `PlanViewModel.packingItems` qua cùng snapshot | Nhóm category, null → Khác; progress từ status; quantity giữ exact string; assignee chỉ hiện “Đã phân công”. Không checkbox/action hoặc Activity completion. |
| Trip Map | `/trips/:tripId/map` | Đọc `selectedLocations` và `activities` qua cùng snapshot | List/filter/detail hoạt động khi provider unavailable. Tọa độ chỉ parse sau finite/range validation; không tải tile/script ngoài. Mobile detail là sheet không modal trong document flow. |

Các route workspace dùng `handle.section` và `NavLink`; `/trips/new` được khai báo trước dynamic trip route. Shared snapshot chỉ ready khi membership/canRead, trip ID, plan/export revision và toàn bộ row `planVersion` đồng nhất.

## Common screen contract

Mỗi screen contract phải ghi:

1. `screen_id`, Figma page/frame/node và route.
2. Actor, authentication và capability/permission.
3. Entry points, exit points và route transitions.
4. View model được UI sử dụng.
5. Query/command repository interface.
6. Loading, success, empty, error, forbidden, conflict và unavailable state.
7. Validation, duplicate-submit và retry behavior.
8. Desktop/tablet/mobile layout, vùng cuộn và keyboard/focus behavior.
9. Data mode: `fixture` hoặc `gateway`.
10. Acceptance criteria và test evidence.

### Query / mutation / adapter gate

- `ShellRepository.read` và `TripRepository.listTrips` đã có với fixture/Gateway cùng interface. Các feature interface khác bên trên chưa tạo; phải chốt typed model từ verified projection trước code. Fixture/Gateway cùng interface/result, permission, error/correlation/retryable và version/revision; không tự điền tên/avatar/budget/provider thiếu projection.
- Write intent giữ expected revisions/idempotency đúng endpoint. Timeout/503 không success, không tự tăng version hoặc dùng generic polling. Auth/Profile không có key contract chung để blind replay.
- CreateTrip basic: name/description/startAt/endAt/timezone/clientRequestId; extras/cover blocked. UpdateTrip: name/description/publicDescription + expected Plan/Export revisions; dates/destination/budget/reminders blocked.
- Profile upload và attach avatar là 2 bước; push-device khác auth session. Policy initial selected-editor read và member profile còn gap; không dùng fixture/write response mẫu thay initial read.
- Location/Dress/Packing chỉ Plan read projection; Packing completion không dùng Activity endpoint. Finance/Admin commands không có body/permission/version đã verify nên không tự định nghĩa.
